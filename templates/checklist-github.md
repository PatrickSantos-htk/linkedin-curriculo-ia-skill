# Checklist de auditoria do GitHub

## Perfil
- [ ] Nome completo, igual ao do LinkedIn e do currículo
- [ ] Bio com cargo + stack principal (até 160 caracteres), coerente com o título do LinkedIn
- [ ] Empresa e localização corretas
- [ ] Links do portfólio e do LinkedIn
- [ ] Foto profissional (a mesma do LinkedIn ajuda no reconhecimento)

## README de perfil
- [ ] Está num repositório público com o **nome exato do seu usuário** (senão ele não aparece no perfil)
- [ ] Sobre mim curto, coerente com o LinkedIn
- [ ] Projetos principais em destaque, com link, funcionalidades e stack
- [ ] Ícones da stack só com tecnologias que você domina
- [ ] Nenhuma promessa que você não sustenta numa entrevista (ex.: CI/CD, microsserviços)
- [ ] Sem o nome do empregador atual, se você quer discrição

## Repositórios fixados
- [ ] Até 6, com os projetos mais fortes primeiro (reais, com cliente, com IA ou com testes)
- [ ] Nenhum repositório de exercício simples entre os fixados

## Cada repositório fixado
- [ ] Descrição de uma frase: o que é + stack
- [ ] Link do site ou demo, quando houver
- [ ] 4 a 6 topics (ex.: react, typescript, nestjs)
- [ ] README explicando o projeto, como rodar e as tecnologias (sem o README padrão do template)

## Coerência
- [ ] Tecnologias do README e dos topics aparecem no currículo e no LinkedIn, e vice-versa
- [ ] Ferramentas que aparecem só no código (ex.: Docker, Jest) foram confirmadas por você antes de entrar no currículo
